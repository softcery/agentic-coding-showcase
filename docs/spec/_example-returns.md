# 06 — The Return ★

The figures a holder files with the Authority (the SPC Return). **The differentiator.** Replaces the consultant's manual three-pass filtering with one action, and — uniquely — **locks in** a submitted return so any later change is flagged automatically with full provenance. _No travel back-office system does this today._

> Several rules here await the consultant's voice note. The **shape** is settled (lock-in is a snapshot; discrepancy detection is a comparison of locked-vs-live; everything folds from the same booking history). The **bases** — booked / departed / forward — are now `✅ VERIFIED` against the guidance note (`06-R1`, `06-R6`). The remaining **grain** question (holder total vs by booking type) is `⚠️ PENDING` (`06-R5`).

## Rules — Generating the return

**Basis & cadence** — ✅ VERIFIED (Authority SPC docs · the guidance note)

- `06-R1` ✅ A Standard return carries **two bases together** (the Authority's return form Part 1): **Part A — passengers booked** (booking-date basis = the cert's **declared (current) issue date**, `02-R2`) and **Part B — passengers departed** (departure-date basis, `04-R3`, `G5`). The Authority **acts on the departure figure**; the booked figure is what generates SPC (`04-R1`). **SBS** report **both** bases too (`00`). **Forward (Part C)** is filed by **all** types (Authority 2025 change); the grain branches on **cadence** — **monthly** files the per-month 12-month breakdown, **quarterly** (Standard <£5m **and** SBS) a **flat per-category total**, no temporal split (`06-R6a`).
- `06-R2` ✅ **IMPLEMENTED** (`084`) Cadence is **not** a free-standing tier:
  - **Standard <£5m turnover** → **quarterly** (departure basis).
  - **Standard ≥£5m turnover** → **monthly**.
  - **SBS** → **quarterly report** (booking + departure basis), **SPC paid annually**.
  - **Scheme-to-Scheme** sales → separate **quarterly** return even for monthly filers.
    Cadence is therefore **derived** from licence type + turnover, not chosen. (the consultant confirms each client's type — Q6.) Monthly + quarterly ship as a **holder property** (`report_cadence`, Authority-assigned, operator-set) that grains every return surface — list, lock, discrepancy, the backdate warning — off the holder's real cycle (`084-R3`). **Carve-outs still deferred**: the **SBS** annual-SPC cadence (the cadence union is left open for it, `084-R7`) and the **Scheme-to-Scheme** separate quarterly return for a monthly filer.
- `06-R3` The system may still expose a **flexible generate-by month or quarter** view for working/preview. ⚠️ whether holders can pick the **filed** cadence, or it's fixed by `06-R2` (Q7). Default: filed cadence is fixed by type/turnover; flexible mode is preview-only.

**Auto-generation**

- `06-R4` A holder/consultancy selects a **period** → the system **auto-generates the return figures** in one action. This replaces manual filtering across booked / departed / forward views.
- `06-R5` ⚠️ PENDING (Q1) — **anatomy**: is a return one holder total, or split by **booking type** (Flight Only / Single / Multi)? Any further breakdown (per agent, destination, month)? Default assumption: **split by booking type**, matching the consultant's category filtering.
- `06-R6` ✅ **Bases in one return** (verified · the guidance note, the return form Part 1). The return carries **booked (Part A)**, **departed (Part B)**, and **forward** figures together (mirrors the three-pass process), with **departure-basis** as the figure the Authority acts on. Booked windows on the **declared (current) issue date** (`02-R2`); departed on the **departure date** (`04-R3`); the two **need not fall in the same period** for one booking. A later **issue-date amend** (backdate correction) re-windows the booked basis without un-booking the figure (`06-R7a`). The booked basis is **per increment** (`04-R5`): the original passengers window on the issue date, each **later-added passenger** on its **own declared booked date** — so a passenger added in a later period counts in **that** period's Part A (its delta only), not the original (the Authority cross-period rule, `06-R18`).
- `06-R6a` ✅ **Forward-booking breakdown is part of the return** (Authority Jan-2025 change): Standard holders report bookings that **depart AFTER the end of the reporting period** (the guidance / the guidance note; Authority 2025 SBS wording: _"depart after the end of the reporting period"_) — a **per-month figure for each of the 12 months following the period end**, plus a single **month-13-onwards** total. The 12-month walk **anchors on the month after the period end**, NOT the period's own first month: an **in-period departure is Part B's, never Part C's** — counting it in both double-counts the period and shifts the horizon by the period length. One membership rule, `departsForward(departureDate) = departureDate > periodEnd`, drives both the filed breakdown and the discrepancy forward axis (`06-R18`), so they can never disagree. **Part C's grain branches on cadence** (`reporting-gold-spec` §3): **monthly** filers (Standard ≥£5m, the schedule) file the **per-month 12-month breakdown** (+ month-13-onwards); **Standard-quarterly** filers (the schedule) file the **per-quarter breakdown** — the **next 4 quarters + a >12-month tail** ("broken down by the quarter those passengers are due to travel, if within the next 12 months"). **SBS** forward grain is **unsourced** — the Authority 2025 SBS-forward change text isn't in the standard-terms-2018 base, so flat-per-category vs by-quarter is unconfirmed (a flat total is the working default; confirm with Authority/the consultant). Membership is identical for all: `departureDate > periodEnd`. The discrepancy forward axis windows on the **locked period's own** end, so the horizon shifts with cadence by construction. The build matches the source: a per-quarter breakdown for Standard-quarterly, per-month for monthly, a flat total for SBS — the quarterly-forecast shape (`08-R8/R9`) the forecast feeds into the return.

**Three-tier reconciliation** (preserve exactly — the regulatory reconciliation)

- `06-R7` Every **departure-basis (Part B)** figure is presented at **three levels** (the regulatory reconciliation):
  1. **Written** — raw original figures, exactly as first issued (`02-R4`) — the reconciliation start, **including** bookings later cancelled.
  2. **After errors** — Written minus **all cancellations**: `Certificate Created in Error` / `Duplicate Certificate` (`03-R11`) **and** genuine `Cancellation` — a cancelled booking **never departs** (`06-R7b`), so it leaves every departed figure.
  3. **After cancellations and changes** — only still-active bookings, counted at their **current** (amended) figures.
     With genuine cancellations absent from **both** lower tiers, **After-errors and After-changes agree** on the departed basis — they differ only by amendments to still-active bookings. (Part A booked keeps genuine cancels, `06-R7a`; the SPC levy is booked-basis, `04-R1`.)
- `06-R7a` **Booked basis (Part A)** carries **two** levels only — **Written** and **After errors** — never an after-changes tier: a booking is **not un-booked** by a later cancellation or amendment (`04-R1` charges at booking). Genuine **`Cancellation`** stays in Part A; only `Certificate Created in Error` / `Duplicate Certificate` drop at After-errors (`03-R11`).
- `06-R7b` **Cancellation by basis.** A genuine `Cancellation` (`03-R10`) is a real booking that **still owes SPC** (`03-R13`, `04-R4`): it **stays in Part A** (booked) and the **SPC line**, and is **excluded from Part B** (departed) and from **forward** — it never departs. `Certificate Created in Error` / `Duplicate Certificate` are **excluded from both bases** and **void SPC** (`03-R11`). The **opening balance** (`07`) has no booking date — it folds into **Part B + forward only**, never Part A.
- `06-R8` All three tiers must reconcile and be reproducible by replay of the booking history to the period. **Filed Forward (Part C) is not a parallel snapshot** — it is the **after-changes (departed-basis) fold restricted to forward-departing active bookings** (`departsForward(currentDeparture) = departure > periodEnd`, `06-R6a`), the **opening balance included** (`06-R7b`). Part B and Part C are **one departed mechanism partitioned by the period-end horizon**: departs **in** the period → Part B, departs **after** it → Part C — never both. (The **discrepancy** forward axis, `06-R18`, is a distinct, narrower fold — the **booked** units gated by `departsForward` — measuring what the filed snapshot was missing at lock; same name "Part C", different basis.)

**Opening balance in the return**

- `06-R8a` A holder's **opening balance** (`07`) folds into the return's **passenger and revenue** tiers for periods it covers — so the return reconciles against the operator's true position from day one.
- `06-R8b` By default the opening balance contributes **no platform SPC** (`07-R9`) — its SPC was handled before onboarding. The return therefore shows opening-balance passengers in the reconciliation tiers but **not** in the SPC figure. ⚠️ PENDING (Q9) — confirm opening balance is pax/revenue-only for SPC purposes, or whether any opening SPC must carry.

## Rules — Submission channel

- `06-R8c` ✅ **There is no Authority submission API.** The statutory return is filed **only** by a human, two ways: the **Scheme Portal** web form ("Manage existing TPS → SPC Return") or a **paper return**. SPC payment is auto-collected by **Direct Debit on submission** — so figure _entry_ is the manual cost, not payment.
- `06-R8d` The system makes that entry trivial: it outputs figures **pre-shaped to the Portal's exact fields** (incl. the forward-booking 12-month breakdown, `06-R6a`) so the operator copies them in fast and error-free, plus an optional **auto-filled paper-return PDF** fallback.
- `06-R8e` **No browser automation / RPA** against the Portal — brittle, auth-gated, ToS-grey. The human files; the system prepares and then records (lock-in).

## Rules — Lock-in

> **We never submit to the Authority.** The statutory submission is made by a human on the Authority **Scheme Portal** — by the **holder** (`12-R4`); a consultancy filing on the holder's behalf is a deferred path. Lock-in records _what was filed_; it is the integrity anchor of discrepancy detection.

- `06-R9` Lock-in is a **deliberate "confirm what you filed" step**, not a silent snapshot (UX `14`). The operator files the generated figures on the Portal, then locks in: the system **freezes a snapshot** of those figures with a server timestamp and the acting identity.
- `06-R9a` The lock-in captures, alongside the figure snapshot: an **attestation** that these are the figures filed, and an **optional Authority Portal submission reference + date**. This keeps the snapshot a trustworthy claim about the Portal, not an assumption.
- `06-R10` A locked snapshot is **immutable**. It records exactly what was filed, for like-for-like comparison later.
- `06-R10a` ⚠️ **Deferred** (consultancy path, `12-R4`). When a **consultancy** locks-in on a holder's behalf, the system would send the holder a **filing record** (`10-R6a`): the attested figures, the optional Portal reference + date, and who filed.
- `06-R11` ⚠️ PENDING (Q3) — **lock grain**: whole period at once, or per booking type independently? Default: lock the **whole period**.
- `06-R12` ⚠️ PENDING (Q5) — **who locks**: holder, consultancy on the holder's behalf, or both. Default: both permitted; the action is audited with the actor.

## Rules — Post-lock discrepancy detection (the core)

- `06-R13` After a period is locked, **any booking change affecting that locked period** is **flagged automatically**. A change "affects" a locked period when a booking's contribution to that period **on any basis** moves **after** the lock timestamp — **Part A** (the **declared issue date** falls in the locked period), **Part B** (the **departure date** falls in the locked period), or **Part C** (the booking is **booked in the locked period** — issue date in it — but **departs a future month beyond it**, so it belongs in the locked period's **forward snapshot**, `06-R6a`). A backdate into an already-locked period re-windows Part A and is caught on the booked axis even when the booking departs in a different period; if that later period is a future month, the same backdate also restates Part C (`06-R18`).
- `06-R14` Each flag is **transparent**: it names the **certificate / booking reference**, the **timestamp** of the change, the **passenger and revenue delta**, the **basis** it breaks (**booked**, **departed**, or **forward**), and the **figure it breaks** versus the locked snapshot. One flag per **(booking, basis)** broken.
- `06-R15` This covers **late/backdated certificates** (`G2`): backdating is a **real declared path** (`02-R2`), not impossible by construction. An agent may issue or amend with a past issue date; a backdate into a period already filed re-windows Part A and **raises a booked-basis discrepancy** with full provenance — surfaced here, with the prescribed prior-period amendment, instead of in the consultant's manual back-end digging.
- `06-R16` ⚠️ PENDING (Q4) — **corrections**: when a discrepancy is resolved by re-filing with the Authority, does the system create a **new locked snapshot** (superseding, with a supersede link), or **annotate** the original? Default: **supersede** — a new snapshot, the prior retained, the delta recorded.
- `06-R17` Discrepancy flags drive a notification to the holder and/or consultancy (`10`) and a dashboard indicator (`11`).
- `06-R18` The per-(booking, basis) discrepancies **aggregate to a prescribed per-period amendment**: per locked period a post-lock change broke, the **booked (Part A), departed (Part B), and forward (Part C) deltas** (`Σ` the discrepancy rows by basis) plus the period's **ΔSPC** (`spc(now) − spc(@lock)`, booking-date basis, `04-R1,R7a`) — the exact figures the holder re-files against **the period the change relates to**, listing the contributing bookings. The **forward (Part C) axis carries no SPC** — it is a **point-in-time snapshot** (the guidance note monitoring, `06-R6a`), not the levy — and is the **booked-unit fold gated by `departsForward`** (the discrepancy axis, distinct from the filed Part C snapshot, `06-R8`): it **restates only when a unit booked in the locked period departing a future month was missing from its forward snapshot at lock** — a backdate that was live before the lock yet recorded after. A **genuine post-lock add** (booked after the lock), a **genuine post-lock cancellation** (stays booked on the levy/forward axis, `06-R7b`), and a **future→future reschedule** (booked dates unmoved, both months still forward) do **not** restate Part C — the snapshot was right at lock. Three Part C edge cases that **do** move: an **error/duplicate cancellation** restates Part C **down** — it voids the unit on the booked **and** forward axes alike (`06-R7b`), unlike a genuine cancel; a **horizon-crossing reschedule** moves a unit **between** Part B and Part C (one basis up, the other down, each its own row); a pure **within-forward month reshuffle** (both months beyond the horizon) is **below the period-total axis grain** — the filed per-month breakdown shifts but no discrepancy is raised, the at-lock snapshot standing. An **ordinary new booking** issued **after** the period that legitimately changes future months is **not** a discrepancy — it is the next period's figure, `G2`. It is **never rolled into the current period** (the issue / departure date decides the period, `G2`); a change whose dates fall only in an **open** period raises **no** amendment — it folds into that period's live return. The amendment is a **derived projection** (`fold(now) − fold(@lock)`), not new state; resolution is **re-lock** (`06-R16` supersede): a fresh lock captures the corrected figures, the delta → zero, the amendment folds away.

## Acceptance

- `06-A1` **Given** a period's return figures, **when** the holder locks it, **then** an immutable snapshot is stored with timestamp and actor, and re-locking the same period is refused (or supersedes, per `06-R16`).
- `06-A2` **Given** a locked Q1, **when** a new certificate departing in Q1 is issued after the lock, **then** a discrepancy flag appears naming the booking ref, change time, and pax/£ delta vs the locked figures.
- `06-A3` **Given** a locked Q1, **when** an active booking departing in Q1 is amended after the lock, **then** a discrepancy flag records the delta.
- `06-A4` **Given** a locked Q1, **when** a booking departing in **Q2** is issued after the lock, **then** **no** Q1 discrepancy is raised.
- `06-A5` **Given** a return, **when** generated, **then** the Written / After-errors / After-changes tiers each reconcile to a replay of the booking history to that period.
- `06-A6` **Given** a fixed booking-event history and period, **when** the return is generated twice, **then** the figures are identical (reproducible).
- `06-A7` **Given** a discrepancy resolved by a correction, **when** re-locked, **then** (default) a new snapshot supersedes the old, the old remains retrievable, and the delta is recorded.
- `06-A8` **Given** a booking issued in Q1 departing in Q1 then later cancelled as **`Cancellation`**, **when** the Q1 return generates, **then** it **appears in Part A (booked)** and the **SPC line**, and is **absent from Part B (departed) and forward**; **when** instead cancelled as **`Duplicate Certificate`**, **then** it is **absent from both bases** and **no SPC** is owed.
- `06-A9` **Given** a locked Q1, **when** a certificate is issued (or its issue date amended) with an issue date **in Q1** after the lock, **then** a discrepancy flag appears on the **booked (Part A)** basis naming the booking ref, change time, and pax/£ delta — even if the booking departs in a later period.
- `06-A10` **Given** an **open** period, **when** a certificate is backdated with an issue date in that period, **then** **no** discrepancy is raised and the booking folds into Part A when that period files.
- `06-A11` **Given** a locked Q1, **when** a certificate is backdated into Q1 (or a Q1-departing booking is amended / cancelled) after the lock, **then** an **amendment-owed** record for Q1 prescribes the Δpax / Δ£ (by basis) and ΔSPC to re-file and lists the contributing bookings; **when** instead the change falls only in an **open** period, **then** **no** amendment is raised (it folds into the live return); **when** the period is then re-locked, **then** the amendment clears (`06-R16,R18`).
- `06-A12` **Given** a locked Q1, **when** a certificate **booked in Q1 but departing a future month** (e.g. Q3) is recorded after the lock (a backdate that was live before it), **then** the prescribed amendment shows a **Part C (forward) delta** alongside the Part A delta — and **no SPC** on the forward axis; **when** instead an **ordinary new booking** for a future month is issued after the period, **then** **no** forward amendment is raised (it is the next period's figure, `06-R18`, `G2`).
- `06-A13` **Given** an Oct–Dec return with a booking departing **in-period** (November) and one departing **after** the period (February), **when** the forward (Part C) breakdown computes, **then** only the February booking is in Part C and the November one is in Part B only — no double-count; the filed breakdown and the discrepancy forward axis agree on membership (`06-R6a`, `06-R18`).
